九宫格模板 v2｜嵌入现有项目说明

一、目标
这份 HTML 是九宫格新版视觉/交互参考实现。正式嵌入时不要整体替换现有项目架构，而是复用现有主题变量、状态保存、DLsite RJ 导入、导出 Canvas 和图片编辑器。

二、需要从现有九宫格删除/改掉的旧设计

1. 删除九宫格额外外围虚线
现状：完整版 .card::before 已有 inset:16px 实线，.card::after 已有 inset:30px 虚线；.grid9-card::before 又额外画了 inset:28px 虚线，导致两条虚线几乎重叠。
修改：删除现有 .grid9-card::before 的外围虚线规则；九宫格直接继承完整版 .card::before / .card::after，保持同样的 16px 实线 + 30px 虚线。

2. 删除“选中当前格”的可见外框
删除 .grid9-cell.is-selected 的 box-shadow。selectedGrid9Index 如内部逻辑仍需使用可保留，但不要显示视觉选中态。新版批量 RJ 导入不再依赖“当前格”。

3. 删除每格右下角 X
现有 .grid9-cell-remove 视觉像删除整格，实际只删 BK。DOM 中不再创建这个按钮，也删除对应 click 分支。重新上传/重新导入时直接覆盖当前 BK；全局已有一键清空。

4. 短标题宽度
现状 width:fit-content; min-width:50%。
修改为 width:100%，与 BK 完全等宽；高度约 38~40px；保留主题色渐变、白字、胶囊圆角；maxLength 可继续 8。

5. RJ 号位置
删除 BK 下方独立 RJ 行。将 RJ input 移入 .grid9-cover-box：position:absolute; right:8~10px; bottom:8~10px；字号约 11~13px；半透明白底、小圆角。
“显示RJ号”只控制最终展示/导出。编辑状态仍需保留可填写能力；若关闭显示，可让 input 变淡而不是 display:none，否则无法填写 RJ 供导入使用。

6. 显示开关文案
改为：☑ 显示编号 / ☑ 显示RJ号。
它们是编辑 UI，不进入导出图片。

7. 短评视觉
不加完整圆角大框。改成轻便签/信纸风：左侧 3px 浅主题色竖线、左上轻量引号/小爱心、底部细线、右下小星芒；背景仅 3~6% 主题浅色。最多三行，字号约 15~18px，line-height 1.4~1.45。

8. BK 视觉
有图：4:3、14~16px 圆角、2~3px 白色描边、外层 1px 主题浅描边、轻阴影。
无图：主题色虚线上传框，不加阴影。
编号：左上悬浮，比现版略小，白底 + 主题色描边。

三、模板外工具栏
现有 .grid9-tool-dock 使用 absolute + bottom:18px，被画在 1080×1440 模板内部。
修改：整个工具栏移出 .grid9-card，放在模板预览下方，不参与导出。
只保留：
1. 按RJ一键导入BK
2. 短标题预设

“短标题预设”做按钮 + popover/dropdown：总结型 / 声优 BEST9 / 以后继续加。
删除：工具栏 RJ 输入框、上一格、下一格。

四、RJ 批量导入逻辑
现状：工具栏单 RJ → selectedGrid9Index → 导入一张 → 自动选下一空格。
新版：每格自己的 .grid9-rj-input 就是数据源。
点击“按RJ一键导入BK”后扫描 9 格：
- RJ 为空：跳过
- RJ 有效 + BK 为空：调用现有 fetchProductJson / parseDlsiteProduct / fetchImageAsPngDataUrl
- RJ 有效 + BK 已存在：默认跳过，避免无意覆盖
- 单格失败不终止整个批次
- 最终反馈成功/未填写/失败数量
建议并发 2~3 个，不要九个请求同时发。

五、九格图片编辑
可以保留，而且不需要 9 套 Canvas。
九格共用现有 imageEditModal + imageEditCanvas：点击已有 BK → activeGrid9Index=index → 将该格当前 BK 载入现有修图器 → 编辑 → 完成后把最终扁平化 PNG 写回该格。
点击空 BK 则正常 file input 上传。

第一版不要为每格分别保存 original / mosaic mask / blur mask / undo-redo / sticker project。当前 grid9 cover 已以 dataURL 进入 collectGrid9State，整个项目又写 localStorage，九张图再保存完整修图工程很容易触发容量问题。
推荐九宫格 v1 每格只保存最终处理图；以后要保留可逆工程再迁 IndexedDB。

六、状态数据
每格继续保留：
{ cover:"...", tag:"...", review:"...", rj:"RJ..." }
删除 grid9.importRj（原工具栏单 RJ）。
showNumbers / showRj 继续保留。

七、Canvas 导出必须同步改
目前九宫格不是 DOM 截图，而是 drawGrid9Card()/drawGrid9Cell() 手动画 Canvas，所以只改 CSS 会出现“预览新版、导出旧版”。
需要同步：
1. 短标题固定使用整格宽度 w，不再按文本动态算 tagWidth
2. 删除 rjRowHeight
3. RJ 改到 BK 右下角的小半透明 badge
4. BK 增加白边 + 主题浅描边 + 轻阴影
5. 短评绘制加入左竖线/引号/底部分隔线/小星芒
6. coverHeight、reviewTop 重新计算
7. 外围框沿用完整版 16px 实线 + 30px 虚线

建议把 DOM 与 Canvas 共用的关键尺寸提成同一组常量/design tokens，避免以后两套越来越不一致。

八、移动端
- 最终模板仍保持 3×3，预览整体缩放，不重排成单列
- 工具栏位于模板外
- 点击单个 BK 打开现有全屏/弹窗修图器
- 不显示 selected 外框
- RJ input 缩放后可能难点，可在手机 focus 某格时临时放大/弹出简单输入层，但不要改变导出布局

九、这份 Demo 里仅用于演示、不要照搬的部分
- “按RJ一键导入BK”使用本地 SVG 占位模拟，没有真正请求 DLsite
- 图片编辑弹窗只是演示“9 格共用一套编辑器”，正式项目请直接复用现有图片编辑器
- 字体用了系统字体；正式项目继续使用现有 BlackSugarPlumCandy 与 canvasFont
