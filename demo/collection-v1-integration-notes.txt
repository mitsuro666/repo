我的收藏 v1｜嵌入现有项目说明

一、定位

“我的收藏”是独立于模板编辑器的管理模块，用来保存、检索、筛选和查看已经录入过的乙抓档案。

核心定位：
- 模板编辑器 = 制作分享图
- 我的收藏 = 管理长期档案
- 单部作品档案页 = 查看一条记录的完整信息

收藏页不需要再额外做“标签视图 / 最近编辑”两个独立页面。
这些功能可以直接通过：
- 标签筛选
- 排序
完成。

二、推荐整体结构

桌面端：
- 左侧 App 主导航保持不动
  - 模板编辑
  - 修图工具
  - 我的收藏
- “我的收藏”激活时，主区域显示收藏列表
- 点击某条作品后，主区域直接切换成完整档案详情
- 不使用 modal 弹窗作为正式详情页

手机端：
- 收藏首页仍使用底部一级导航
- 点击作品进入档案详情后，隐藏底部一级导航
- 顶部显示：
  ← 返回我的收藏
  编辑
  ⋯
- 返回收藏页后再恢复底部导航

三、收藏首页

1. 顶部
建议保留：
- 页面标题：我的收藏
- 新建记录
- 导入备份
- 导出备份

可以把导入/导出放在次级位置，“新建记录”作为主要操作。

2. 搜索
搜索范围建议包括：
- 日文标题
- 中文标题
- CV
- RJ号
- 社团
- 收藏标签

3. 标签筛选
收藏标签与作品关键词必须分开。

作品关键词：
- 描述作品内容/属性
- 例如：青梅竹马、病娇、ASMR、年上

收藏标签：
- 用户自己用于管理作品
- 例如：喜欢、一般、史低90、待重听、2026 TOP

数据字段建议：
{
  "keywords": [],
  "libraryTags": []
}

一个作品可以拥有多个 libraryTags。

4. 排序
初版建议：
- 最近编辑
- 评分高 → 低
- 购入时间
- 购入价
- CV

“最近编辑”不需要单独做页面，直接作为排序选项。

5. 展示方式
建议保留：
- 网格
- 列表

默认网格。

四、收藏卡片

网格卡片重点展示 BK。

推荐比例：
- BK 占主要视觉面积
- 下方只显示：
  CV
  RJ号

标题可以：
- 桌面 hover 时浮层显示
- 手机不依赖 hover，可在长按/详情中看

不建议给每条记录塞太多字段，否则收藏首页会变得很重。

五、点击作品后的详情逻辑

不要使用正式 modal。

推荐：
libraryView
→ 收藏列表

detailView
→ 单部作品档案

点击某条记录：
1. 记录当前滚动位置
2. 隐藏 libraryView
3. 显示 detailView
4. 更新当前档案内容
5. 滚动到顶部

返回：
1. 隐藏 detailView
2. 显示 libraryView
3. 恢复之前的滚动位置
4. 保留之前的搜索 / 标签 / 排序状态

这样用户从第4排点进去，返回后仍然停在原位置。

六、档案详情页

档案页不要复用 3:4 分享模板布局。

它应该是完整的“作品档案页”，更像资料页，不像导出卡片。

推荐结构：

顶部：
← 我的收藏
编辑
⋯

主信息：
- BK
- 日文标题
- 中文标题
- CV
- 社团
- RJ
- 系列
- 时长
- 购入价
- 原价
- 评分

标签：
- 作品关键词
- 我的收藏标签

正文：
- 作品简介
- 角色资料
- 我的评价
- Repo / 感想

后续可扩展：
- 剧情记录
- 购买记录
- 重听记录
- 状态：未听 / 已听 / 待重听
- 官方语言版本
- 同系列作品

视觉原则：
- 少用大圆角盒子
- 用标题、分隔线、留白形成层级
- 不要把每一段都塞进卡片

七、档案页操作

顶部建议：
← 我的收藏      编辑      ⋯

“编辑”：
- 打开现有模板编辑器
- 自动载入当前这条记录
- 修改后保存回同一份档案数据

“⋯”：
- 生成分享图
- 导出此记录
- 删除记录

生成分享图时：
- 从同一条档案数据读取
- 完整版 / 简略版 / 九宫格只读取需要的字段
- 不要分别维护三套数据

八、数据结构

核心原则：
一份档案 = 唯一数据源。

例如：
{
  "id": "record_xxx",
  "rj": "RJ01152097",
  "titleJa": "",
  "titleZh": "",
  "cv": "",
  "circle": "",
  "series": "",
  "duration": "",
  "cover": "",
  "keywords": [],
  "libraryTags": [],
  "prices": {},
  "ratings": {},
  "summary": "",
  "character": "",
  "review": "",
  "createdAt": "",
  "updatedAt": ""
}

完整版模板、简略版模板、九宫格都读取这一条记录的不同字段。

比如改 CV：
档案数据更新一次
→ 所有模板再次读取时都得到新 CV

九、存储建议

设置类：
localStorage

作品档案和 BK：
优先 IndexedDB

原因：
- 收藏数量后期会变多
- BK 属于图片 Blob
- localStorage 容量有限
- Base64 图片很容易把 localStorage 撑满

初期若暂时继续使用 localStorage 也可以，但正式做收藏模块时建议尽早切 IndexedDB。

每条记录需要稳定 id：
record_xxxxx

不要使用：
- 标题
- RJ号
作为唯一主键。

因为：
- 用户可能保存没有 RJ 的作品
- RJ 可能存在不同语言版
- 标题可能被编辑

十、备份

初版可以支持 JSON：
- 导出全部档案
- 导入全部档案

如果 BK 也以 Base64 存 JSON：
优点：简单
缺点：文件会很大

后续收藏量增多后建议升级：
ZIP
├ records.json
└ images/
   ├ record_xxx.png
   └ record_yyy.png

数据建议带：
schemaVersion

例如：
{
  "schemaVersion": 1,
  "records": [...]
}

以后字段结构变化时可以做迁移。

十一、与现有模板编辑器联动

推荐流程：

我的收藏
↓
点击一部作品
↓
档案页
↓
编辑
↓
模板编辑器载入同一条 record
↓
保存
↓
更新档案
↓
返回档案页

不要复制一份数据到模板编辑器再另存。

十二、未来很适合追加，但不属于 v1 必做

- 批量选择
- 批量添加/移除收藏标签
- 批量导出
- 从收藏选择 9 部直接生成九宫格
- 自定义拖拽排序
- 智能分组
- 重听历史
- 最近编辑记录
- 收藏统计
- CV / 社团聚合页

其中“从收藏选择 9 部 → 九宫格”很适合后续和九宫格模板联动。

十三、v1 推荐最终范围

必做：
1. 收藏网格
2. 搜索
3. 收藏标签筛选
4. 排序
5. 网格 / 列表切换
6. 点击作品进入完整档案页
7. 返回后保留列表状态和滚动位置
8. 编辑当前档案
9. 备份导入 / 导出

暂时不做：
- 标签视图独立页
- 最近编辑独立页
- 复杂统计
- 批量管理
- 重听历史
- 智能分组

十四、Demo 与正式项目的区别

之前的 HTML Demo 主要是交互和信息架构参考：
- 里面的 BK 是 CSS / 占位图，不是真实档案
- 详情数据是 mock data
- “编辑档案 / 生成分享图”只是演示按钮
- 正式项目应直接读取现有档案数据
- 正式项目最好用 IndexedDB 保存记录和 BK
- 左侧导航、手机底栏应直接复用当前 App Shell

最重要的设计结论：
1. 收藏首页不再增加“标签视图 / 最近编辑”二级 Tab
2. 标签 = 筛选
3. 最近编辑 = 排序
4. 详情页不用 modal
5. 点击记录后主区域直接切换为档案详情
6. 返回时恢复原来的收藏列表状态
